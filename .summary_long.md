# Athanor Root Directory - Detailed Analysis

## Project Overview

Athanor is a sophisticated Electron-based desktop application designed to revolutionize AI-assisted development workflows. It serves as a bridge between developers and AI assistants (ChatGPT, Claude, Gemini) by providing intelligent context management and automated change integration capabilities.

### Core Value Proposition

1. **API-Key Free Core Workflow**: Unlike many AI development tools, Athanor's primary workflow doesn't require API keys. Users copy prompts to their preferred AI assistant and paste responses back.

2. **Intelligent Context Discovery**: The Relevance Engine automatically discovers and includes contextually relevant files beyond manual selection, using Git history, code dependencies, and user activity patterns.

3. **Controlled Change Management**: AI-generated changes are parsed, presented as visual diffs, and can be individually accepted or rejected before any modifications to disk.

## Architecture & Technology Stack

### Electron Architecture
- **Main Process** (`electron/`): Handles file system operations, Git integration, and system-level services
- **Renderer Process** (`src/`): React-based UI with Zustand state management
- **IPC Bridge**: Secure communication via `preload.ts` with types in `src/types/global.d.ts`

### Key Technologies
- **Electron 33+**: Desktop application framework
- **React 19+**: UI framework with hooks and functional components
- **TypeScript 5+**: Strict typing across the entire codebase
- **Zustand**: Lightweight state management solution
- **TailwindCSS 3**: Utility-first CSS framework with dark mode support
- **Material-UI 6**: Component library for consistent UI elements
- **Jest & ts-jest**: Testing framework with TypeScript support
- **Webpack**: Module bundler with separate configs for main/renderer/preload
- **Electron Forge**: Build and packaging toolchain

### External Dependencies
- **genai-lite**: Unified LLM integration (Claude, GPT, Gemini, Mistral)
- **genai-key-storage-lite**: Secure API key storage
- **Chokidar**: File system watching
- **ignore**: .gitignore/.athignore pattern matching
- **js-tiktoken**: Accurate token counting for prompts
- **node-pty & xterm**: Terminal emulation (CLI feature)

## Development Guidelines

### Code Standards
- **TypeScript**: Strict typing required
- **React**: Functional components with hooks
- **Formatting**: Prettier (single quotes, semicolons, 80 char width)
- **Linting**: ESLint configuration exists but incompatible with v9+
- **Commits**: Conventional Commits format required
- **DCO**: All commits must be signed off (`git commit -s`)

### Architecture Principles
1. **Separation of Concerns**: Main process handles system operations, renderer handles UI
2. **Security First**: All file operations go through IPC bridge
3. **Type Safety**: Global types in `src/types/global.d.ts` must be maintained
4. **Service Pattern**: Core functionality encapsulated in services (FileService, GitService, etc.)

### Key Services & Components

#### Main Process Services
- **FileService**: Central file system operations manager
- **GitService**: Repository analysis and history
- **RelevanceEngineService**: Intelligent context discovery
- **ProjectGraphService**: Background project analysis
- **SettingsService**: Application and project settings
- **ShellService**: Terminal session management
- **UserActivityService**: File activity tracking

#### Renderer Process Stores
- **fileSystemStore**: File tree and selection state
- **workbenchStore**: Multi-tab task management
- **contextStore**: Intelligent context builder state
- **promptStore**: Prompt templates and variants
- **taskStore**: Task templates and presets
- **applyChangesStore**: AI change management
- **settingsStore**: UI settings state
