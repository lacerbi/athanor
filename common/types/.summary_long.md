# Directory: common/types

## Overview

The `common/types/` directory defines the type contracts for cross-process communication in Athanor's Electron architecture. These interfaces ensure type safety between the privileged main process and the sandboxed renderer process, forming the foundation for secure IPC communication. The directory contains three core interface files that define contracts for file system operations, Git integration, and LLM service communication.

## Key Components

### file-service.ts

Comprehensive interface definition for all file system operations within Athanor. The `IFileService` interface provides a complete abstraction layer over Node.js file system operations, ensuring consistent path handling and secure file access across the application.

**Core Interface Methods:**
- **Path Utilities**: `toUnix()`, `toOS()`, `join()`, `dirname()`, `basename()`, `extname()`, `resolve()`, `relativize()`
- **File Operations**: `read()`, `write()`, `remove()`, `exists()`, `stats()`, `isDirectory()`
- **Directory Management**: `ensureDir()`, `readdir()` with optional ignore pattern support
- **File Watching**: `watch()` method returning unsubscribe function with typed event callbacks
- **Base Directory**: `setBaseDir()`, `getBaseDir()` for project root management
- **Ignore Rules**: `reloadIgnoreRules()`, `isIgnored()` for `.gitignore`/`.athignore` support
- **Resource Paths**: `getAppPath()`, `getResourcesPath()`, `getPromptTemplatePath()`

**Key Design Decisions:**
- All paths internally use Unix-style notation for consistency
- Methods accept both relative and absolute paths
- Watch callbacks always provide project-relative paths
- Clear distinction between project files and application resources
- Built-in support for fs.Stats type from Node.js

### git-service.ts

Defines interfaces for Git repository operations, enabling version control integration throughout the application. The `IGitService` interface provides methods for querying repository state and history.

**Main Interface - IGitService:**
- `setBaseDir()`, `getBaseDir()`: Repository root management
- `isGitRepository()`: Check if directory is a Git repository
- `getCommitsForFile()`: Retrieve commit history for specific files
- `getFilesForCommit()`: List files changed in a specific commit
- `getRecentlyCommittedFiles()`: Find files changed within time window
- `getRecentCommitHashes()`: Get recent commit identifiers
- `getUncommittedChanges()`: List pending changes
- `getContentAtHead()`: Retrieve file content from HEAD

**Supporting Types:**
- `CommitLog`: Structure containing hash, message, author, and date
- `GitFileStatus`: File path with status code ('A', 'M', 'D')
- `GitDiffData`: Extended file status including old and new code content
- `GitCommitsForFileOptions`: Query options with maxCount and since parameters

### llm.ts

Minimal but crucial type definitions for LLM (Language Model) integration. Defines IPC channel constants for secure communication with AI services.

**Channel Constants (LLM_IPC_CHANNELS):**
- `GET_PROVIDERS`: 'llm:get-providers' - Retrieve available LLM providers
- `GET_MODELS`: 'llm:get-models' - Get models for a specific provider
- `SEND_MESSAGE`: 'llm:send-message' - Send messages to LLM service
- `IS_KEY_AVAILABLE`: 'llm:is-key-available' - Check API key status

**Type Definitions:**
- `LLMIPCChannelName`: Union type of all channel names for type-safe IPC communication
- Uses const assertion pattern for compile-time safety

## Architecture & Design

The types directory follows several important architectural patterns:

1. **Interface Segregation**: Each service has its own interface file, avoiding monolithic type definitions
2. **Pure Type Definitions**: No implementation code, only contracts and type definitions
3. **Async-First Design**: All I/O operations return Promises for non-blocking execution
4. **Options Objects**: Complex methods use options parameters for extensibility
5. **Consistent Naming**: Clear conventions (get*, is*, to*) for method purposes

## Dependencies

### Internal Dependencies
- Imports only TypeScript type definitions
- References Node.js fs module types for Stats interface

### External Dependencies
- No runtime dependencies
- Pure type definitions compatible with TypeScript 5+

## Integration Points

### Main Process Integration
- Implementations in `electron/services/` directory
- FileService.ts implements IFileService
- GitService.ts implements IGitService
- LLM handlers implement channel contracts

### Renderer Process Integration
- Types exposed via `src/types/global.d.ts`
- Accessed through window.electronAPI
- Full IntelliSense support in renderer code

### IPC Bridge
- Types used in `preload.ts` for secure context bridge
- Channel names used in IPC handler registration
- Ensures type safety across process boundaries

## Usage Examples

### File Service Usage
```typescript
// In renderer process
const content = await window.electronAPI.readFile('src/main.ts');
const stats = await window.electronAPI.stats('package.json');
const unwatch = window.electronAPI.watchFile('src', (event, path) => {
  console.log(`File ${event}: ${path}`);
});
```

### Git Service Usage
```typescript
// Get recent commits for a file
const commits = await window.electronAPI.git.getCommitsForFile('README.md', {
  maxCount: 10,
  since: '2024-01-01'
});

// Check uncommitted changes
const changes = await window.electronAPI.git.getUncommittedChanges();
```

### LLM Channel Usage
```typescript
// In main process handler
ipcMain.handle(LLM_IPC_CHANNELS.GET_PROVIDERS, async () => {
  return ['anthropic', 'openai', 'google', 'mistral'];
});
```
