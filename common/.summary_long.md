# common/

## Overview

The `common/` directory serves as the shared contract layer between Electron's main and renderer processes. It contains type definitions that ensure type safety across the IPC (Inter-Process Communication) boundary, preventing runtime errors and enabling IntelliSense support in both processes. This directory is crucial for maintaining Athanor's security model while providing a rich, typed API surface.

By centralizing these type definitions, the codebase ensures that both the main process services and the renderer process consumers share a single source of truth for API contracts. This prevents drift between implementation and usage, a common source of runtime errors in Electron applications.

## Key Components

### types/

The types subdirectory contains interface definitions for core services exposed through Electron's IPC mechanism:

- **file-service.ts**: Defines `IFileService` interface for comprehensive file system operations including path manipulation, file I/O, directory management, file watching, and resource access. Notable features include Unix/OS path conversion, ignore rules integration, and distinction between project paths and application resource paths.

- **git-service.ts**: Defines `IGitService` interface and related types for Git repository operations. Includes types for commit logs, file status tracking, and methods for analyzing repository history, uncommitted changes, and file content at specific commits.

- **llm.ts**: Defines IPC channel constants and types for LLM (Large Language Model) integration. Provides type-safe channel names for operations like getting providers, models, sending messages, and checking API key availability.

## Architecture

The common directory follows a strict organizational pattern:

1. **Pure Types Only**: No implementation code, only TypeScript interfaces and type definitions
2. **Process Agnostic**: Types can be imported by both main and renderer processes without issues
3. **Service Contracts**: Each interface represents a complete service API that will be implemented in the main process
4. **IPC Channel Definitions**: Constants for IPC channel names ensure consistency across the codebase

## Dependencies

The common directory has minimal dependencies:
- **TypeScript**: For type definitions
- **Node.js fs types**: Used in file-service.ts for `fs.Stats` type compatibility

## Integration Points

The types defined here are used throughout the application:

1. **Main Process Services**: Implement these interfaces (e.g., `FileService` implements `IFileService`)
2. **IPC Handlers**: Use these types to ensure handler parameters match the interface
3. **Preload Script**: Exposes methods conforming to these interfaces via `contextBridge`
4. **Renderer Process**: Consumes services through these typed interfaces via the global window object
5. **Type Definitions**: `src/types/global.d.ts` extends the window interface with these service types
