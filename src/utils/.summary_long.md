# src/utils

## Overview

The utils directory contains the foundational utility functions that power Athanor's core functionality. These utilities handle everything from file tree operations and selection management to prompt building and token counting. The code demonstrates excellent software engineering practices with comprehensive error handling, type safety, and performance optimizations.

## Key Components

### Prompt Generation System

#### buildPrompt.ts
The main orchestrator for AI prompt generation:
- **Dynamic Prompt Building**: Core function `buildDynamicPrompt` assembles complete prompts from templates
- **Variable Management**: Handles 20+ template variables including project info, file contents, and task descriptions
- **Template Rendering**: Uses `renderTemplate` from genai-lite for variable substitution with conditional logic
- **Configuration Integration**: Respects user settings for file tree inclusion, format type, and smart previews
- **Supplementary Materials**: Separates regular files from materials using "materials:" prefix
- **Format Flexibility**: Supports both XML and Markdown documentation formats
- **Smart Preview Config**: Configurable preview lines (min/max) with fallback to constants

#### promptTemplates.ts
Template loading and task extraction utilities:
- **Template Loading**: Async loading from resources directory via Electron IPC
- **Task Extraction**: Extracts task descriptions from XML tags in templates
- **Error Handling**: Proper error propagation with descriptive messages
- **Path Resolution**: Uses main process for secure template path resolution

#### codebaseDocumentation.ts
Generates structured documentation for AI consumption:
- **File Tree Visualization**: ASCII art tree with selection indicators (*) and folder markers (/)
- **Smart Preview System**: Intelligently truncates files at natural boundaries (empty lines)
- **Multi-Format Support**: Both Markdown (with syntax highlighting) and XML output
- **Content Organization**: Separates regular content from supplementary materials
- **Language Detection**: Maps file extensions to languages for syntax highlighting
- **Project Info Deduplication**: Avoids duplicating project info file content
- **Binary File Filtering**: Skips non-text files based on detection

### File System Operations

#### fileTree.ts
Core data structures and tree operations:
- **FileItem Interface**: Central type with id, name, type, path, children, lineCount, error, isEmpty
- **Tree Traversal**: Functions for getting descendants, finding items by ID
- **Sorting Logic**: Folders before files, alphabetical within each type
- **Empty Detection**: Recursive empty folder detection for UI display
- **Path Utilities**: `getBaseName` for cross-platform filename extraction
- **ID Management**: Efficient ID-based lookups avoiding full tree traversal

#### fileSelection.ts
Selection state management for the file explorer:
- **Descendant Selection**: Functions to check if all/some descendants are selected
- **Selectable Items**: Filters out empty folders from selection
- **Line Counting**: Calculates total lines across selected files
- **Set Operations**: Efficient selection checking using Set data structure
- **Array/Set Compatibility**: Handles both array and Set inputs for flexibility

#### fileOperations.ts
AI-generated change application engine:
- **Diff Block Parsing**: Extracts SEARCH/REPLACE blocks from AI responses
- **Matching Strategies**: Two-stage approach - exact match first, then fuzzy patch
- **Line Ending Normalization**: Handles Windows (CRLF), Unix (LF), and Mac (CR)
- **diff-match-patch Integration**: Uses Google's library for fuzzy matching
- **Error Handling**: Detailed error messages for debugging failed patches
- **Decorative Comment Handling**: Fixed regex to avoid matching separator lines in comments
- **Strict Mode**: Optional strict matching for testing scenarios

#### fileTextDetection.ts
Binary vs text file detection:
- **Extension-Based Fast Path**: 50+ known text extensions for quick detection
- **Content Analysis**: Analyzes file bytes for 80% printable character threshold
- **Buffer Handling**: Adapts to various Electron buffer formats (ArrayBuffer, string)
- **Performance Limits**: Analyzes only first 256KB for large files
- **Character Classes**: Recognizes printable ASCII + whitespace (tab, LF, CR)
- **MIME Pattern Support**: Ready for MIME-based detection (currently unused)

### Configuration and Constants

#### constants.ts
Centralized configuration repository:
- **Documentation Formats**: Default XML format for AI consumption
- **File System Settings**: Material directory name, refactoring thresholds
- **Application Defaults**: Smart preview lines, token limits, theme settings
- **UI Configuration**: Animation timings, menu dimensions, button states
- **Context Builder Weights**: Detailed scoring for relevance engine (20+ factors)
- **Project Analysis**: Timing settings for background analysis triggers
- **Drag & Drop**: MIME types and CSS classes for file dragging

#### configUtils.ts
Configuration resolution with precedence system:
- **Precedence Chain**: Project settings → Auto-discovery → Fallback values
- **Project Name Resolution**: Override → Directory name fallback
- **Project Info Discovery**: Settings path → Auto-discovery → Empty
- **AI Summaries Setting**: Configurable with true as default
- **Error Resilience**: Falls back gracefully at each level
- **Settings Integration**: Works with ProjectSettings type

#### projectInfoUtils.ts
Project documentation discovery and reading:
- **Auto-Discovery**: Searches for project/about/index/readme files
- **Case Insensitive**: Handles various naming conventions cross-platform
- **Extension Priority**: Checks .md then .txt for each basename
- **Content Normalization**: Consistent line endings and XML wrapping
- **Path Resolution**: Handles both relative and absolute paths
- **Validation**: Checks file existence and ensures it's not a directory

### Language and Analysis Tools

#### languageMapping.ts
Comprehensive language detection for syntax highlighting:
- **130+ Extensions**: Maps to react-syntax-highlighter language identifiers
- **Grouped Languages**: Related extensions share language settings
- **Special Files**: Handles Dockerfile, Makefile, config files
- **Build Files**: Recognizes package.json, pom.xml, etc.
- **Fallback Logic**: Unknown extensions default to 'text'
- **CommonJS Export**: Compatible with the syntax highlighter library

#### contextDetection.ts
Automatic context extraction from task descriptions:
- **Commit Detection**: Finds "# Commit X:" patterns in task text
- **Context Types**: Extensible interface for future context types
- **Relevance Checking**: Validates contexts still apply to content
- **Formatting**: Converts raw patterns to user-friendly display text
- **Source Tracking**: Maintains original text for relevance checks

#### tokenCount.ts
OpenAI-compatible token counting:
- **GPT-4 Encoding**: Uses cl100k_base tokenizer from js-tiktoken
- **Singleton Pattern**: Caches tokenizer instance for performance
- **Error Handling**: Returns 0 on errors with console warnings
- **Formatting Utilities**: Human-readable display with ~prefix and commas
- **Significant Digits**: Rounds to 3 significant digits for display
- **Empty Input Handling**: Graceful handling of null/empty strings

### Utility Functions

#### extractTagContent.ts
Simple XML content extraction:
- **Focused Purpose**: Extract content between opening and closing tags
- **String Operations**: Uses indexOf and slice for efficiency
- **Error Handling**: Returns empty string when tags not found
- **Whitespace Trimming**: Automatically trims extracted content

### Testing

#### fileOperations.test.ts
Comprehensive test suite demonstrating:
- **Diff Parsing Tests**: Various SEARCH/REPLACE block formats
- **Edge Cases**: Empty blocks, decorative comments, special characters
- **Normalization Tests**: Line ending conversions, whitespace handling
- **Fuzzy Matching**: Tests for both exact and fuzzy patch scenarios
- **Error Scenarios**: Invalid blocks, missing content, strict mode failures
- **Real-World Cases**: Multi-line code blocks, complex decorations

## Design Patterns

### Functional Programming
Most utilities are pure functions:
- No side effects on global state
- Predictable input/output relationships
- Easy to test and reason about

### Error Resilience
Comprehensive error handling:
- Try-catch blocks with logging
- Fallback values for failures
- Validation of inputs
- Detailed error messages

### Performance Optimization
- Extension lookups use O(1) HashMaps
- ID-based lookups avoid tree traversal
- Singleton pattern for expensive objects
- Early returns for invalid inputs
- Lazy evaluation where appropriate

### Type Safety
Full TypeScript typing:
- Explicit interfaces for data structures
- Proper return type annotations
- Union types for flexibility
- No use of 'any' type

### Cross-Platform Compatibility
- Path normalization for Windows/Unix
- Line ending handling (CRLF/LF/CR)
- Case-insensitive file matching
- Buffer format adaptation

## Integration Points

### Main Process Communication
All file operations go through Electron IPC:
- window.fileSystem API for file access
- Async/await pattern throughout
- Proper error propagation

### Store Integration
Utilities are used by Zustand stores:
- fileSystemStore uses selection utilities
- contextStore uses detection utilities
- promptStore uses template utilities

### Component Usage
React components consume utilities:
- File explorer uses tree utilities
- Code viewer uses language mapping
- Prompt builder uses documentation generators

## Performance Considerations

1. **Caching**: Tokenizer instance cached as singleton
2. **Early Returns**: Quick paths for common cases
3. **Efficient Algorithms**: O(1) lookups where possible
4. **Memory Management**: Limits on buffer sizes
5. **Lazy Loading**: Templates loaded only when needed

## Best Practices Demonstrated

1. **Single Responsibility**: Each file has one clear purpose
2. **DRY Principle**: Shared logic extracted to utilities
3. **Defensive Programming**: Input validation throughout
4. **Clear Naming**: Functions and variables self-document
5. **Consistent APIs**: Similar patterns across utilities
6. **Comprehensive Documentation**: Inline comments explain complex logic

This utility collection provides a robust foundation that enables Athanor's sophisticated features while maintaining code clarity, testability, and performance.
