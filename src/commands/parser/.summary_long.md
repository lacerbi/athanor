# /home/luigi/athanor/src/commands/parser

## Overview

This subdirectory contains specialized XML parsing logic for the command system, handling the complexities of AI-generated XML content. The parsers are designed to be robust and lenient, accommodating various formatting quirks and escape patterns that may appear in AI output.

## Key Components

### applyChangesParser.ts

The most complex parser in the system, handling file operation commands with sophisticated XML parsing.

#### XmlParser Class

A stateful sequential parser that tracks position through the XML content:

```typescript
class XmlParser {
  private content: string;
  private position: number;
  
  // Methods for navigating and extracting content
  private skipWhitespace(): void
  private findNext(search: string, errorContext: string): number
  private extractTagContent(tagName: string): string
  private parseCdataBlock(): string
  private parseFileBlock(): FileBlock | null
  public parseFileBlocks(): FileBlock[]
}
```

#### Key Features

1. **Sequential Processing**
   - Tracks position through content
   - Provides context for error messages
   - Handles nested structures cleanly

2. **CDATA Block Handling**
   - Supports standard `<![CDATA[...]]>` blocks
   - Lenient parsing for missing `]]>` markers
   - Fallback to `</file_code>` detection

3. **File Operation Parsing**
   - Extracts: message, operation, path, code
   - Validates operation types (CREATE, UPDATE_FULL, UPDATE_DIFF, DELETE)
   - Enforces operation-specific rules

4. **Smart Operation Conversion**
   - CREATE → UPDATE_FULL for existing files
   - Provides warnings for conversions
   - Tracks failed diff operations

### commandParser.ts

Handles the extraction of command blocks from clipboard content.

#### Core Functions

1. **normalizeLineEndings(text: string)**
   - Converts all line endings to Unix format
   - Ensures consistent parsing across platforms

2. **unescapeAthCommandTags(text: string)**
   - Handles multiple escape patterns:
     - `&lt;` → `<`
     - `&amp;lt;` → `<`
     - `\\<` → `<`
   - Only unescapes ath command tags
   - Preserves content integrity

3. **extractAllCommandBlocks(content: string)**
   - Uses regex to find all `<ath command="...">` blocks
   - Validates command types against COMMAND_TYPES
   - Preserves full XML for apply_changes commands

4. **parseCommand(clipboardContent: string)**
   - Main entry point for command parsing
   - Supports both single and multiple commands
   - Returns null for invalid content

#### Command Interface

```typescript
export interface Command {
  type: CommandType;
  content: string;
  fullContent?: string; // For apply_changes commands
}
```

## Design Philosophy

### Lenient Parsing

The parsers are intentionally lenient to handle AI-generated content:

1. **Multiple Escape Patterns**: AI models may escape XML differently
2. **Flexible CDATA Handling**: Accommodates missing end markers
3. **Graceful Degradation**: Continues parsing despite errors
4. **Context in Errors**: Shows where parsing failed

### Sequential vs Regex

- **commandParser.ts**: Uses regex for simple command extraction
- **applyChangesParser.ts**: Uses sequential parsing for complex nested structures

This hybrid approach optimizes for both performance and accuracy.

## Error Handling Strategies

### Parsing Errors

1. **Position Tracking**: Shows where in the XML parsing failed
2. **Context Messages**: Describes what was expected
3. **Recovery Attempts**: Tries alternative parsing strategies
4. **Partial Success**: Processes valid blocks even if some fail

### Validation Errors

1. **Field Validation**: Checks required fields are present
2. **Type Validation**: Ensures operation types are valid
3. **Content Validation**: Verifies operation-specific rules
4. **Clear Messages**: Explains what's wrong and why

## Integration with Command System

### Data Flow

1. **Input**: Raw clipboard content with XML
2. **Parsing**: Extract and validate command structure
3. **Transformation**: Convert to internal command format
4. **Output**: Structured command objects for execution

### Parser Selection

- Simple commands → `commandParser.ts`
- File operations → `applyChangesParser.ts`
- Automatic routing based on command type

1. **Sequential Parsing**: O(n) complexity for file operations
2. **Regex Matching**: Efficient for command extraction
3. **Memory Usage**: Processes large files in chunks
4. **Error Recovery**: Minimal performance impact

## Security Considerations

1. **Input Sanitization**: All XML content is validated
2. **Path Validation**: File paths checked before use
3. **No Code Execution**: Parsers only extract data
4. **Escape Handling**: Prevents injection attacks
