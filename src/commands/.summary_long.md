# /home/luigi/athanor/src/commands

## Overview

The commands directory implements a sophisticated XML-based command system that serves as the primary interface between AI assistants and the Athanor application. This system allows AI models to perform various operations like selecting files, updating task descriptions, and applying code changes through a structured, validated command protocol. The architecture emphasizes safety, validation, and user control over AI-suggested actions.

## Command Types

### SELECT Command
Allows AI to specify which files should be selected for context:
```xml
<ath command="select">
src/index.ts src/App.tsx src/utils/helpers.ts
</ath>
```

### TASK Command
Updates the task description in the active workbench tab:
```xml
<ath command="task">
Refactor the authentication module to use JWT tokens
</ath>
```

### APPLY_CHANGES Command
Specifies file modifications with support for multiple operations:
```xml
<ath command="apply_changes">
  <ath_file path="src/auth.ts">
    <ath_action>UPDATE_DIFF</ath_action>
    <ath_diff>
      <![CDATA[
      SEARCH:
      const token = generateToken()
      
      REPLACE:
      const token = generateJWT(user)
      ]]>
    </ath_diff>
  </ath_file>
</ath>
```

### AGENT_TASK Command
Creates task files for AI agents in the materials directory:
```xml
<ath command="agent_task">
  <file_name>analyze_dependencies.md</file_name>
  <task_content>Analyze project dependencies and create upgrade plan</task_content>
</ath>
```

## Key Components

### Command Executors

#### selectCommand.ts
**Execution Flow:**
1. Parses space-separated file paths
2. Validates each path exists in file tree
3. Filters out folders (only files allowed)
4. Updates workbench selection atomically
5. Provides detailed success/failure feedback

**Validation:**
- Checks file existence in current tree
- Ensures only files (not folders) selected
- Reports invalid paths to user

#### taskCommand.ts
**Simple Operation:**
- Validates content is not empty
- Updates active tab's task description
- Logs success or failure

**Integration:**
- Direct workbench store update
- Minimal validation needed

#### applyChangesCommand.ts
**Complex Processing:**
1. Counts tokens for transparency
2. Parses XML to extract operations
3. Clears existing operations
4. Sets new operations in store
5. Switches to review tab

**Features:**
- Token usage reporting
- Diff mode configuration
- Automatic UI navigation

#### agentTaskCommand.ts
**Task File Creation:**
1. Extracts file name and content
2. Validates required fields
3. Creates file in .ath_materials
4. Generates clickable instruction

**Interactive Feature:**
- Log entry copies usage instructions
- Helps users understand task files

### Parser System

#### parser/commandParser.ts
**Robust XML Parsing:**
- Handles multiple escape patterns
- Normalizes line endings
- Extracts command blocks
- Validates command types

**Escape Handling:**
- `&lt;ath` → `<ath`
- `\\<ath` → `<ath`
- Various quote escaping

**Key Functions:**
- `parseCommand()`: Main entry point
- `extractAllCommandBlocks()`: Multi-command support
- `normalizeLineEndings()`: Platform compatibility
- `unescapeAthCommandTags()`: Escape processing

#### parser/applyChangesParser.ts
**Sequential XML Parser:**
- Custom parser for complex structures
- CDATA block handling
- Position tracking for errors
- Lenient parsing for AI output

**Parser Class Features:**
- `XmlParser`: Stateful sequential parser
- Error context in messages
- Fallback strategies for malformed XML
- File operation validation

**Operation Types:**
- CREATE: New file creation
- UPDATE_FULL: Complete file replacement
- UPDATE_DIFF: Search/replace blocks
- DELETE: File removal

**Smart Conversions:**
- CREATE → UPDATE_FULL for existing files
- Failed diff tracking with recovery

## Design Patterns

### 1. Parser-Executor Separation
- Parsing logic isolated from execution
- Enables testing and reuse
- Clear responsibility boundaries

### 2. Validation-First Approach
- All inputs validated before execution
- User-friendly error messages
- Safe operation guarantees

### 3. Interactive Logging
- Clickable log entries
- Additional actions on click
- Enhanced user experience

### 4. Lenient Parsing
- Handles AI-generated quirks
- Multiple escape patterns
- Graceful degradation

## Usage Flow

### AI Integration Flow
1. AI generates XML commands
2. User pastes into Athanor
3. Commands parsed and validated
4. Operations prepared for review
5. User approves/rejects changes

### Manual Task Flow
1. User creates task description
2. AI reads and understands task
3. AI generates appropriate commands
4. Commands update Athanor state
5. Workflow continues

This command system provides a robust, safe interface for AI-assisted development, ensuring that AI suggestions are always under user control while maintaining a smooth, efficient workflow.
