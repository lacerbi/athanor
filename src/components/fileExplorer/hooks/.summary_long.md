# src/components/fileExplorer/hooks/ - Detailed Analysis

## Overview
This directory contains custom React hooks that encapsulate the complex state management and business logic for the file explorer component. By extracting this logic into hooks, the components remain clean and focused on presentation.

## Hook Implementation

### useFileExplorer.ts

A comprehensive custom hook that manages all aspects of file explorer state and behavior:

**State Management:**
- **expandedFolders**: A Set data structure tracking which folder IDs are currently expanded
- **contextMenu**: Nullable state holding position and target item for right-click menus
- **currentDirectory**: String path of the active project directory
- **explorerRef**: React ref for the explorer container element

**Initialization Logic:**
The hook intelligently initializes with sensible defaults:
```typescript
// If single root folder, expand it by default
const [expandedFolders, setExpandedFolders] = useState<Set<string>>(() => {
  if (items.length === 1 && items[0].type === 'folder') {
    return new Set([items[0].id]);
  }
  return new Set();
});
```

**Core Functions:**

1. **toggleFolder(itemId: string)**
   - Toggles expansion state of a single folder
   - Uses Set operations for efficient updates
   - Immutable state updates for React optimization

2. **handleExpandRecursively(item: FileItem)**
   - Expands a folder and all its descendants
   - Uses utility function to gather all descendant IDs
   - Batch updates for performance
   - Only operates on folder items

3. **handleCollapseRecursively(item: FileItem)**
   - Collapses a folder and all its descendants
   - Removes multiple IDs from Set in one operation
   - Filters out collapsed IDs efficiently

4. **handleIgnoreItem(itemPath: string, ignoreAll: boolean)**
   - Adds items to .athignore file
   - Supports both specific paths and wildcard patterns
   - Triggers refresh after successful operation
   - Includes error handling with console logging

5. **handleContextMenu(e: React.MouseEvent, item: FileItem)**
   - Prevents default browser context menu
   - Captures click coordinates
   - Stores target item for menu actions
   - Closes any existing menu first

6. **handleCloseContextMenu()**
   - Simple callback to clear context menu state
   - Used by multiple event handlers

**Side Effects:**

1. **Current Directory Loading**
   ```typescript
   useEffect(() => {
     const loadCurrentDirectory = async () => {
       const dir = await window.fileSystem.getCurrentDirectory();
       setCurrentDirectory(dir);
     };
     loadCurrentDirectory();
   }, []);
   ```
   - Loads project directory on mount
   - Async operation with proper handling

2. **Document Click Handler**
   ```typescript
   useEffect(() => {
     const handleDocumentClick = (e: MouseEvent) => {
       if (explorerRef.current && !explorerRef.current.contains(e.target as Node)) {
         handleCloseContextMenu();
       }
     };
     document.addEventListener('click', handleDocumentClick);
     return () => {
       document.removeEventListener('click', handleDocumentClick);
     };
   }, [handleCloseContextMenu]);
   ```
   - Closes context menu when clicking outside
   - Proper cleanup on unmount
   - Uses ref to check click target

**Return Interface:**
The hook returns a comprehensive object with all necessary values and functions:
```typescript
return {
  explorerRef,              // For container element
  expandedFolders,          // Current expansion state
  contextMenu,              // Menu state
  currentDirectory,         // Active directory
  handleIgnoreItem,         // Ignore functionality
  toggleFolder,             // Single folder toggle
  handleContextMenu,        // Right-click handler
  handleCloseContextMenu,   // Menu dismissal
  handleExpandRecursively,  // Expand all
  handleCollapseRecursively // Collapse all
};
```

## Design Patterns

### Separation of Concerns
- UI logic separated from business logic
- Components handle presentation
- Hook handles state and operations

### Performance Optimization
- Set data structure for O(1) lookups
- Batch state updates
- Memoized callbacks where beneficial
- Minimal re-render triggers

### Error Handling
- Try-catch blocks for async operations
- Graceful failures with console logging
- User feedback through callbacks

### Memory Management
- Event listener cleanup
- No stale closures
- Proper dependency arrays

## Usage Pattern

The hook is designed for easy integration:
```typescript
const {
  explorerRef,
  expandedFolders,
  contextMenu,
  handleIgnoreItem,
  toggleFolder,
  handleContextMenu,
  handleCloseContextMenu,
  handleExpandRecursively,
  handleCollapseRecursively,
} = useFileExplorer(items, onRefresh);
```

Components can then use these values directly without managing complex state.

## Benefits

1. **Reusability**: Logic can be shared across multiple file explorer instances
2. **Testability**: Hook logic can be tested independently
3. **Maintainability**: Changes to logic don't affect component structure
4. **Type Safety**: Full TypeScript support with proper typing
5. **Performance**: Optimized state updates and minimal re-renders
