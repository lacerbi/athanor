# /home/luigi/athanor/src/services - Detailed Analysis

## Overview
This directory contains UI-layer services that handle various aspects of the application's functionality, including file system operations, model preset management, ignore file handling, and prompt/task template loading. These services act as the bridge between the renderer process UI components and the main process services via IPC.

## Key Components

### athanorPresetService.ts
**Purpose**: Manages Athanor model presets for LLM integration

**Key Features**:
- Loads presets from `src/config/athanorModelPresets.json`
- Validates presets against available LLM providers and models
- Provides caching with lazy initialization
- Supports filtering by provider and model
- Validates preset settings (temperature, maxTokens, topP, etc.)

**Key Functions**:
- `getAllAthanorPresets()` - Gets all valid presets
- `getAthanorPresetById()` - Retrieves specific preset
- `getAthanorPresetsByProvider()` - Filters presets by provider
- `reinitializeAthanorModelPresetService()` - Forces refresh when providers change

**Dependencies**:
- `window.electronBridge.llmService` for provider/model validation
- `useLogStore` for logging initialization status

### fileIgnoreService.ts
**Purpose**: Manages .athignore file creation and gitignore integration

**Key Features**:
- Creates .athignore files with optional standard ignore rules
- Augments existing .gitignore files with Athanor-specific rules
- Loads default templates from resources directory
- Handles path normalization for ignore patterns

**Key Functions**:
- `initializeProjectFiles()` - Creates/overwrites .athignore with options
- `addToIgnore()` - Adds paths to ignore file with wildcard support

**Dependencies**:
- `window.fileService` for file operations
- `window.pathUtils` for path manipulation
- Default templates from `resources/files/`

### fileSystemService.ts
**Purpose**: Core service for building and maintaining file tree structure

**Key Features**:
- Recursive directory traversal with ignore support
- Line counting for files
- Content normalization (consistent line endings)
- Support for supplementary materials tree
- Error handling for inaccessible paths

**Key Functions**:
- `buildFileTree()` - Recursively builds FileItem tree structure
- `readFileContent()` - Reads and normalizes file content
- `getAllFiles()` - Extracts all file paths from tree
- `findItemByPath()` - Locates items in tree by path

**Dependencies**:
- `window.fileService` for file operations
- `window.pathUtils` for path joining
- `fileTree` utils for sorting and validation

### promptService.ts
**Purpose**: Loads and manages prompt and task templates

**Key Features**:
- XML parsing for prompt and task templates
- Three-tier template system: default, global user, project-specific
- Override priority: Default < Global < Project
- Templates override by order number, not ID
- Supports both prompt_*.xml and task_*.xml formats

**Key Functions**:
- `loadPrompts()` - Loads all prompt templates and updates store
- `loadTasks()` - Loads all task templates and updates store
- `parseXmlFile()` - Generic XML parser for both types

**XML Structure**:
```xml
<ath_prompt id="..." label="..." order="..." icon="..." tooltip="...">
  <ath_prompt_variant id="..." label="..." tooltip="...">
    Content here
  </ath_prompt_variant>
</ath_prompt>
```

**Dependencies**:
- `usePromptStore` and `useTaskStore` for state management
- `window.fileSystem` for directory operations
- `readFileContent` from fileSystemService

## Architecture Patterns

### Service Layer Design
1. **IPC Abstraction**: Services use window.* APIs exposed through preload
2. **Error Handling**: Comprehensive try-catch blocks with logging
3. **Async Operations**: All file operations are properly async
4. **Type Safety**: Full TypeScript typing for all operations

### State Management Integration
- Services update Zustand stores directly
- Stores handle sorting and deduplication
- Services focus on data fetching and transformation

### File System Patterns
1. **Path Handling**: 
   - Always use path utilities for joining
   - Handle both absolute and relative paths
   - Normalize paths for cross-platform compatibility

2. **Content Processing**:
   - Normalize line endings to Unix format
   - Trim trailing whitespace
   - Ensure single trailing newline

3. **Tree Building**:
   - Recursive traversal with cycle detection
   - Separate handling for materials directory
   - Empty folder detection

## Security Considerations

- No direct file system access from renderer
- Proper error handling for access denied

### Template Loading
