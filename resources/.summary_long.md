# Resources Directory - Detailed Analysis

## Purpose

The `resources/` directory serves as the central repository for Athanor's static assets and templates. It provides the foundation for AI-powered development workflows through carefully crafted prompt templates, default configurations, and visual assets. These resources are embedded within the application and loaded at runtime to ensure consistent, high-quality AI interactions across all projects.

## Directory Structure

### 1. prompts/ - AI Interaction Templates

The core of Athanor's intelligent prompting system, containing XML-based templates that structure AI interactions for various development scenarios.

**Prompt Templates (prompt_*.xml):**

1. **Query Mode** (`prompt_query.xml`): Basic Q&A about codebases
   - Validates file availability before answering
   - Asks clarifying questions for ambiguous queries
   - Ideal for code understanding and exploration

2. **Architect Mode** (`prompt_architect.xml`): Planning implementations
   - Breaks features into phases/commits
   - Creates implementation roadmaps
   - Used before coding to plan approach

3. **Development Mode** (`prompt_develop.xml`): Active coding
   - Tracks file state changes
   - Provides structured XML responses
   - Main mode for code modifications

4. **Minimal Mode** (`prompt_minimal.xml`): Lightweight responses
   - Reduced formatting overhead
   - Faster responses
   - Good for token-constrained scenarios

5. **Metaprompt Mode** (`prompt_metaprompt.xml`): Prompt generation
   - Creates detailed prompts from descriptions
   - Helps build custom workflows
   - Meta-level prompt engineering

6. **Writer Mode** (`prompt_writer.xml`): Documentation focus
   - Optimized for content creation
   - README files, documentation
   - Non-code text generation

7. **Autoselect Mode** (`prompt_autoselect.xml`): Smart file selection
   - Automatically identifies relevant files
   - Uses task description for context
   - Helps when manual selection is unclear

**Task Templates (task_*.xml):**

1. **AI Summary** (`task_ai_summary.xml`): Documentation comments
   - Adds concise summaries to file headers
   - Improves code navigation
   - Requires file selection

2. **PR Changelog** (`task_pr_changelog.xml`): Pull request descriptions
   - Generates comprehensive change summaries
   - Formats for PR templates
   - Git-aware context

3. **Refactor Files** (`task_refactor_files.xml`): Code improvement
   - Applies best practices
   - Modernizes code patterns
   - Requires file selection

4. **Unit Tests** (`task_unit_tests.xml`): Test generation
   - Creates comprehensive test suites
   - Follows project testing patterns
   - Improves coverage

5. **Build Repomap** (`task_build_repomap.xml`): Context mapping
   - Creates hierarchical summaries
   - Enables agentic coding
   - Reduces context bloat

**Template System Features:**
- XML structure with id, order, label, icon, tooltip attributes
- Variant system for multiple modes per template
- Placeholder substitution with `{{variable}}` syntax
- Order-based override system for customization

### 2. files/ - Configuration Templates

Provides default configuration files used during project initialization and setup:

**default_athignore:**
- Comprehensive ignore patterns for development
- Categories include:
  - Version control (.git, .svn, .hg)
  - OS files (.DS_Store, Thumbs.db, desktop.ini)
  - Editors (VS Code, JetBrains, Vim, Emacs)
  - Dependencies (node_modules, vendor, packages)
  - Build artifacts (dist, build, out)
  - Temporary files (.tmp, .cache, logs)
  - Security files (.env, secrets, keys)
- Special Athanor rules for .ath_materials management

**default_gitignore_extras:**
- Additional patterns for .gitignore augmentation
- Preserves prompts and settings while ignoring caches
- Athanor-specific entries for clean repositories

### 3. images/ - Visual Assets

Contains branding and documentation imagery:

**Application Assets:**
- `athanor_logo.png`: Main application branding

**Tutorial Screenshots:**
- `athanor_snapshot.png`: Main interface overview
- `athanor_snapshot_apply_changes.png`: Apply Changes panel demo
- Used in documentation and tutorials

## Implementation Architecture

### XML Template Schema

All templates follow consistent patterns:
```xml
<ath_prompt id="unique-id" order="1" label="Display Name" icon="IconName" tooltip="Description">
  <variant name="default">
    <content><![CDATA[
      Template content with {{placeholders}}
    ]]></content>
  </variant>
</ath_prompt>
```

### Dynamic Placeholder System

Templates utilize a comprehensive placeholder system for dynamic content injection:
- `{{project_name}}`: Current project name
- `{{project_info}}`: Project documentation content
- `{{file_contents}}`: Selected file contents
- `{{file_tree}}`: ASCII tree representation
- `{{task_description}}`: User's task input
- `{{task_context}}`: Additional context
- `{{selected_files}}`: List of selected files
- `{{supplementary_section}}`: Materials from .ath_materials

### Resource Loading Hierarchy

Athanor implements a sophisticated loading hierarchy for maximum flexibility:
1. Project-specific (.ath_materials/prompts/)
2. User global (~/.athanor/prompts/)
3. Default resources (this directory)

Lower order numbers override higher ones with same ID.

## Design Patterns and Best Practices

### Template Development Guidelines

1. **Clear Instructions**: Each template provides focused, unambiguous directives to AI models
2. **Consistent Placeholders**: Standardized variable naming ensures predictable behavior
3. **Logical Ordering**: Templates ordered by frequency of use and workflow importance
4. **Intuitive Icons**: Lucide React icons chosen for immediate visual recognition
5. **Flexible Variants**: Multiple modes per template support diverse use cases

### Configuration Principles

1. **Comprehensive Coverage**: Default ignore patterns cover all major development scenarios
2. **Override Capability**: Users can customize without modifying core resources
3. **Cross-Platform Support**: Patterns work across Windows, macOS, and Linux
4. **Security First**: Sensitive files (.env, keys) excluded by default

## Integration with Main Application

These resources integrate seamlessly with Athanor's core systems:

- **PromptService**: Loads and manages XML templates
- **FileService**: Applies ignore patterns during file operations
- **UI Components**: Display icons and tooltips from template metadata
- **Context Builder**: Substitutes placeholders with actual project data

The modular design allows users to extend functionality by adding custom templates while preserving the integrity of default resources.
