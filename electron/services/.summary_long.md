# /home/luigi/athanor/electron/services - Detailed Summary

## Overview

This directory contains the core business logic services for the Electron main process. These services implement critical functionality including file system operations, Git integration, project analysis, dependency resolution, and intelligent context discovery. The services work together to provide Athanor's advanced features while maintaining clean separation of concerns.

## Core Infrastructure Services

### FileService.ts

The foundational service for all file system operations:

**Core Capabilities:**
- Centralized file I/O with security validation
- Unix-style path normalization (internal standard)
- File watching with chokidar integration
- Ignore rule application (.athignore/.gitignore)
- Materials directory management

**Key Features:**
- Path traversal protection in resolve()
- Event emission for file changes and base directory updates
- Automatic materials directory creation
- Comprehensive error handling with contextual messages
- Singleton pattern with global instance

**Path Operations:**
- `resolve()`: Secure path resolution with validation
- `relativize()`: Convert absolute to relative paths
- `toUnix()/toOS()`: Path format conversion
- `join()`, `dirname()`, `basename()`: Path manipulation

**File Operations:**
- `read()`, `write()`, `remove()`: Basic I/O
- `exists()`, `stats()`, `isDirectory()`: File system queries
- `readdir()`: Directory listing with ignore support
- `getAllFilePaths()`: Recursive file enumeration

### PathUtils.ts

Stateless path manipulation utilities:

**Design Philosophy:**
- Pure functions with no side effects
- Unix-style paths as internal standard
- Platform conversion only at OS boundaries

**Utility Categories:**
- **Normalization**: `normalizeToUnix()`, `toPlatform()`
- **Building**: `joinUnix()`, `resolveUnix()`
- **Analysis**: `isAbsolute()`, `relative()`, `parse()`
- **Validation**: `isPathInside()`, `getAncestors()`
- **System**: `getTempPath()`, `sanitizeFilename()`

**Cross-Platform Support:**
- Handles Windows backslashes
- Preserves UNC paths
- Drive letter handling
- POSIX compliance

## Service Patterns

### 1. Service Pattern
Most services are instantiated and passed as dependencies:
```typescript
const fileService = new FileService();
const gitService = new GitService(baseDir);
```

### 2. Event Emitter Pattern
FileService extends EventEmitter for loose coupling:
```typescript
this.emit('file-changed', { event, path });
this.emit('base-dir-changed');
```

### 3. Async/Await Pattern
All I/O operations use modern async patterns:
```typescript
async read(path: string): Promise<string | Buffer>
```

### 4. Error Handling Pattern
Consistent error handling with context:
```typescript
catch (error) {
  console.error(`Error reading file ${path}:`, error);
  throw error;
}
```

## Performance Optimizations

1. **Caching**: Results cached where expensive (tokenizer, project graph)
2. **Debouncing**: File watch events, analysis triggers
3. **Lazy Loading**: Services initialize on first use
4. **Path Normalization**: Once on entry, maintained internally
5. **Worker Threads**: CPU-intensive work offloaded

## Key Interactions and Integration Points

### Service Dependencies
- **RelevanceEngineService** depends on: FileService, GitService, ProjectGraphService, UserActivityService
- **ProjectGraphService** depends on: FileService, GitService, DependencyScanner, DependencyResolver
- **UserActivityService** listens to: FileService events
- **SettingsService** uses: FileService for I/O operations

### IPC Integration
- Services are exposed to renderer process via handlers in `electron/handlers/`
- Type definitions shared via `common/types/`
- Secure communication through preload script

### External Tool Integration
- **Git**: Command-line interface via child_process
- **node-pty**: Optional dependency for terminal emulation
- **Chokidar**: File system watching
- **js-tiktoken**: GPT-4 compatible tokenization

## Design Patterns and Best Practices

1. **Separation of Concerns**: Each service has a single, well-defined responsibility
2. **Type Safety**: Full TypeScript typing with interfaces from common/types
3. **Error Handling**: Comprehensive error handling with contextual messages
4. **Performance**: Caching, lazy loading, and background processing
5. **Cross-Platform**: Unix-style paths internally, platform conversion at boundaries
6. **Graceful Degradation**: Services handle missing dependencies (Git, node-pty)
7. **Testing**: Comprehensive unit tests with mocked dependencies

This service layer forms the backbone of Athanor's intelligent features, providing robust, performant, and well-tested functionality for understanding project structure and assisting developers with AI-powered context discovery.
