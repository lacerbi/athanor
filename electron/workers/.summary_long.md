# Directory: electron/workers

## Overview

The `workers` directory contains background worker thread implementations that handle CPU-intensive tasks without blocking the main Electron process. This architecture ensures the application remains responsive during heavy computational operations like project analysis.

## Key Components

### projectAnalysisWorker.ts

A dedicated worker thread for comprehensive project analysis:

**Purpose:**
- Offloads expensive project analysis from the main thread
- Prevents UI freezing during large codebase analysis
- Enables parallel processing of project data

**Architecture:**
- Runs as a Node.js Worker Thread
- Communicates via message passing with the main thread
- Creates isolated service instances for analysis

**Workflow:**
1. Receives `baseDir` from main thread via `workerData`
2. Instantiates required services:
   - `FileService` for file system operations
   - `GitService` for version control data
   - `ProjectGraphService` for analysis orchestration
3. Performs complete project analysis
4. Returns analysis results to main thread

**Analysis Operations:**
- Dependency graph construction
- File mention detection
- Shared commit analysis
- Hub file identification
- Recent activity tracking

**Error Handling:**
- Validates worker thread environment
- Checks for required `baseDir` parameter
- Serializes errors for cross-thread communication
- Logs progress and completion status

## Communication Protocol

### Input Message (workerData)
```typescript
{
  baseDir: string  // Absolute path to project root
}
```

### Output Messages (postMessage)

**Success:**
```typescript
{
  success: true,
  data: ProjectGraphData  // Complete analysis results
}
```

**Failure:**
```typescript
{
  success: false,
  error: string  // Serialized error message
}
```

## Integration with Main Process

The worker is spawned from `main.ts` when:
1. File system becomes quiescent (no changes for configured period)
2. User is inactive (window not focused or no recent activity)
3. Previous analysis is outdated or missing

**Spawning Pattern:**
```typescript
const worker = new Worker(path.join(__dirname, 'workers', 'projectAnalysisWorker.js'), {
  workerData: { baseDir }
});
```

## Performance Benefits

1. **Non-blocking**: Main thread remains responsive during analysis
2. **Isolation**: Service instances don't interfere with main process
3. **Scalability**: Can potentially spawn multiple workers
4. **Memory Management**: Worker memory is freed after completion

## Best Practices

1. **Serializable Data**: Ensure all communicated data is serializable
2. **Error Serialization**: Convert Error objects to strings for messages
3. **Resource Cleanup**: Worker terminates after sending results
4. **Logging**: Include console logs for debugging worker execution
5. **Validation**: Always validate input data before processing

## Future Considerations

- Could be extended for other CPU-intensive tasks
- Potential for worker pooling for parallel analyses
- Progress reporting during long-running analyses
- Cancellation support for interrupted analyses

This worker architecture demonstrates excellent separation of concerns and performance optimization for Athanor's intelligent project understanding capabilities.
