# Directory: electron/__tests__

## Overview

The `__tests__` directory contains testing utilities specifically designed for the main process tests. This directory provides mock implementations and helper functions that enable comprehensive unit testing of Electron's main process components without requiring actual file system operations.

## Key Components

### mockFsHelpers.ts

A sophisticated mocking utility for file system operations in Jest tests:

**Core Mock Functions:**
- `mockFsAccess`: Simulates file/directory access checks
- `mockFsStat`: Returns file statistics (directory vs file)
- `mockFsReadFile`: Provides file content simulation
- `mockFsReaddir`: Lists directory contents
- `mockFsWriteFile`: Simulates file writing

**Helper Functions:**
- `setupMockFs()`: Configures a complete mock file system structure
  - Takes a Map of paths to file/directory metadata
  - Optionally takes a Map of file paths to content
  - Simulates realistic file system behavior
- `clearMockFs()`: Resets all mocks between tests

**Implementation Details:**
- Replaces the entire `fs/promises` module
- Handles path normalization (backslash to forward slash)
- Throws proper Node.js errors (ENOENT, ENOTDIR) with correct error codes
- Supports both empty files and files with content
- Enables testing of directory structures and file hierarchies

## Usage Patterns

### Setting Up Mock File System
```typescript
const files = new Map([
  ['/project', { isDirectory: true, files: ['file1.ts', 'file2.ts'] }],
  ['/project/file1.ts', { isDirectory: false }],
  ['/project/file2.ts', { isDirectory: false }]
]);

const content = new Map([
  ['/project/file1.ts', 'export const hello = "world";'],
  ['/project/file2.ts', 'import { hello } from "./file1";']
]);

setupMockFs(files, content);
```

### Testing File Operations
The mocks enable testing of:
- File existence checks
- Directory listings
- File reading with proper error handling
- Path resolution and validation
- Directory vs file differentiation

## Best Practices

1. **Isolation**: Each test should set up its own file system structure
2. **Cleanup**: Always call `clearMockFs()` in afterEach hooks
3. **Realistic Structures**: Create mock structures that mirror real project layouts
4. **Error Testing**: Include tests for missing files and invalid paths
5. **Path Consistency**: Use forward slashes for cross-platform compatibility

## Integration with Main Process Tests

These utilities are used throughout the main process test suites:
- FileService tests use them to simulate file operations
- Path utilities tests verify path handling without real I/O
- Ignore rules tests simulate .gitignore and .athignore files
- Service tests can mock entire project structures

The mock helpers ensure tests run quickly, predictably, and without side effects on the actual file system.
